# AI 엔지니어링 강의 — 시연 앱 사용법

강의 「AI 리터러시 · 프롬프트 엔지니어링 · RAG」의 Part 1(s03~s07)을 Anthropic API
실호출로 보여주는 **PromptOps 콘솔** 사용법입니다. 발표자가 무대에서 무엇을 누르고
무엇이 보이는지를 순서대로 적었습니다.

- 설치·배포·리허설 체크리스트 같은 기술 사항은 [`demo/README.md`](../../demo/README.md)에 있습니다.
- 이 앱은 **GitHub Pages에 올라가지 않습니다.** `/api/generate`가 서버 라우트라
  정적 export에 담기지 않습니다. 강의 덱은 Pages, 시연 앱은 Vercel로 따로 배포합니다.

## 여는 방법

| 환경 | 주소 | 준비 |
|---|---|---|
| **배포(발표용)** | **https://ai-engineering-demo.vercel.app/promptops** | 없음 — 키가 Vercel에 등록돼 있습니다 |
| 로컬 | `http://localhost:3100/promptops` | `demo/.env.local`에 `ANTHROPIC_API_KEY`, `npm run build:snippets` 후 `npm run dev` |

발표는 배포 주소로 하는 편이 안전합니다(로컬 dev 서버는 노트북 절전·포트 충돌에 걸립니다).

`npm run build:snippets`를 먼저 돌리지 않으면 `코드` 탭이 동작하지 않습니다(스니펫이
저장소에 없는 생성물입니다).

## 화면 구조

```
[ s03 무작위성 ] [ s05 지시 방법 ] [ s06 안티패턴 ] [ s07 구조화 출력 ]   ← 프리셋 탭
프리셋 설명 한 줄

┌── 조작 ────────────┐  ┌── 요청 | 코드 | 응답 ──────────────┐
│ [프리셋 전체 실행]  │  │                                    │
│ 변형 버튼들         │  │  요청: 지금 서버로 갈 JSON 전문     │
│ MODEL / EFFORT      │  │  코드: 그 값이 지나가는 실제 소스   │
│ TEMPERATURE …       │  │  응답: 스트리밍 출력 · 토큰 수      │
│ MAX_TOKENS          │  │        · 검증 결과 · 에러          │
│ SYSTEM / USER       │  │                                    │
└─────────────────────┘  └────────────────────────────────────┘
```

**실행 버튼이 두 개입니다. 차이를 알고 쓰세요.**

| 버튼 | 위치 | 무엇을 하나 |
|---|---|---|
| `프리셋 전체 실행` | 왼쪽 위 | 그 프리셋의 **모든 변형을 병렬 호출**해 결과를 열로 나란히 보여줍니다. 비교가 목적일 때 씁니다. |
| `실행` | `응답` 탭 안 | 왼쪽 조작부의 **현재 요청 하나만** 호출합니다. 값을 직접 만져 보여줄 때, 그리고 저장된 응답 폴백이 걸리는 유일한 경로입니다. |

**핵심 대응 관계:** 왼쪽 슬라이더·셀렉트·체크박스를 만지면 `요청` 탭 JSON의 필드가
즉시 바뀝니다. TOP_P·TOP_K는 `추가`/`제거` 버튼으로 **키 자체가 생기고 사라집니다** —
"파라미터를 안 보내는 것"과 "0을 보내는 것"이 다르다는 이야기를 여기서 하면 됩니다.

## 슬라이드별 조작 순서

### s03 무작위성 — 프리셋 `무작위성`

1. 프리셋 탭에서 **무작위성** 선택 → `프리셋 전체 실행`
2. 같은 프롬프트(무선 이어폰 광고 문구 한 문장)를 `temperature 0`과 `temperature 1.0`으로 **각 5회** 호출합니다(총 10회).

보이는 것: 왼쪽 열(0)의 5개는 거의 같은 문장, 오른쪽 열(1.0)은 눈에 띄게 갈립니다.
`코드` 탭에는 `temperature`가 Messages API 파라미터로 들어가는 `buildMessageParams`가
그대로 나옵니다.

말하기: 같은 입력에 같은 답이 나오지 않는 이유가 이 값 하나라는 것. 분류·추출처럼
매번 같아야 하는 작업은 0으로 내린다는 것.

### s05 지시 방법 — 프리셋 `지시 방법`

1. **지시 방법** 선택 → `프리셋 전체 실행` (3열, 호출 3회)
2. 같은 리뷰에 Zero-shot / Few-shot / CoT 세 구성을 보냅니다.

보이는 것: 3열이 뜨고 **CoT 열의 출력 토큰 수가 가장 큽니다**(관측치 370 vs 255 vs 178).
각 열 머리에 출력 토큰 수가 붙습니다.

말하기: CoT가 늘 좋은 게 아니라 **비용이 붙는다**는 것. 세 방식의 차이가 결국 `messages`
배열의 문자열 하나라는 것 — `코드` 탭의 `buildPatternPrompt`가 그 지점입니다.

### s06 안티패턴 — 프리셋 `안티패턴`

1. **안티패턴** 선택 → `프리셋 전체 실행` (4열, 2×2로 배치, 호출 4회)
2. 덱의 네 가지 중 두 가지가 나쁜 예/고친 예 짝으로 들어 있습니다: **① 모호한 지시**,
   **③ 한 번에 여러 작업**.

보이는 것:

| 짝 | 나쁜 예 | 고친 예 |
|---|---|---|
| ① 모호한 지시 | "리뷰 좀 정리해줘" → 요약인지 분류인지 모델이 추측해 형식이 흔들립니다 | 한 단어 분류를 지시 → 짧고 일정합니다(관측치 6토큰) |
| ③ 한 번에 여러 작업 | 요청하지 않은 것(이모지 머리글·별점 표)을 덧붙이고 형식이 흔들립니다(관측치 256토큰) | 1)2)3) 라벨을 정확히 지킵니다(관측치 107토큰) |

**주의:** 최신 haiku는 작업을 통째로 누락하지 않습니다. 무대에서 할 이야기는 "뒤 작업이
빠진다"가 아니라 **"요청하지 않은 것까지 붙고 형식이 흔들려 뒤의 코드가 파싱하기
어렵다"**입니다(덱 표의 증상 칸도 그렇게 고쳐 두었습니다).

### s07 구조화 출력 — 프리셋 `구조화 출력`

1. **구조화 출력** 선택 → `프리셋 전체 실행` (3열, 호출 최대 5회)
2. 세 변형입니다.

| 변형 | 무엇이 다른가 | 보이는 것 |
|---|---|---|
| `자유 텍스트` | 그냥 감성을 물어봄 | 문장이 옵니다 — 파싱 불가 |
| `JSON 스키마 강제` | `output_config.format`으로 스키마 강제 | 한 줄 JSON + **`1회차 검증 통과`** |
| `JSON 요청 — 형식 강제 없이` | 프롬프트로만 JSON을 요구, 서버는 같은 스키마로 **검증만** | `N회차 검증 실패` + 문제 목록 → `— 재요청 N회차 —` → 최대 2회 재요청 후 정지 |

말하기 순서가 덱 본문 네 줄과 그대로 맞습니다: **왜**(자유 텍스트가 파싱 안 됨) →
**어떻게**(스키마 강제) → **그래도 깨진다**(강제 없이 요구하면 코드 펜스·설명이 섞여
검증에 걸림) → **상한을 둔다**(재요청 2회에서 멈춤).

`코드` 탭에는 `validateAgainstSchema`가 나옵니다 — 형식을 강제해도 **받는 쪽에서
확인한다**는 태도가 이 슬라이드의 요점입니다.

> 모델 출력은 비결정적입니다. `형식 강제 없이` 변형이 운 좋게 1회차에 통과할 수도
> 있습니다. 그러면 "이번엔 통과했다"고 말하고 넘어가면 됩니다 — 강제한 쪽은 **원리적으로**
> 통과하고, 강제하지 않은 쪽은 **운에 달렸다**는 대비 자체가 요점입니다.

## 모델 전환 400 시연 (s03·s04 어디서든)

1. `MODEL`을 `claude-opus-5`로 바꿉니다 → `요청` 탭 JSON에서 `temperature`가 **사라지고**
   `effort`가 생기며 `max_tokens`가 자동으로 올라갑니다
2. **"temperature를 강제로 전송"** 체크박스를 켭니다 → JSON에 `temperature`가 다시 나타납니다
3. `응답` 탭에서 `실행` → 벽돌색 박스에 **`HTTP 400 · BadRequestError`**와 API가 준 메시지가 뜹니다
4. 체크박스를 끄고 다시 `실행` → **정상 응답이 나옵니다**

4번이 중요합니다. 400만 보여주고 끝내면 시연이 막다른 길처럼 보입니다.

**주의 두 가지**

- **무작위성 프리셋에서 이 시연을 하지 마세요.** 그 변형의 `max_tokens`가 64인데,
  opus-5는 thinking이 기본으로 돌고 `max_tokens`가 **사고+응답 합계 상한**이라 빈 출력으로
  끝날 수 있습니다. **지시 방법**처럼 `max_tokens`가 넉넉한 프리셋에서 하세요.
- `EFFORT`에 `xhigh`·`max`가 없는 것은 의도된 것입니다. 그 두 값은 6만 토큰 규모의 예산을
  요구해 이 시연의 상한에서는 빈 출력이 됩니다.

## API가 죽었을 때

키가 만료됐거나 네트워크가 끊기면 **`저장된 응답`** 배지와 함께 리허설 때 기록해 둔 실제
응답이 표시됩니다(12개 저장돼 있습니다). 조건은 두 가지입니다.

- **`실행`(단일) 경로에만** 걸립니다. `프리셋 전체 실행`에는 폴백이 없습니다.
- 왼쪽 조작부를 만지지 않은 상태여야 합니다 — **변형 버튼을 눌러 고른 뒤 `실행`**하세요.
- `HTTP 400`은 폴백하지 않습니다. 400은 시연 재료라 그대로 보여줍니다.

응답이 SSE 프레임 없이 끊기면 `NetworkError` 또는 `NoFrames` 박스가 뜨고 `실행` 버튼이
다시 살아납니다. 화면이 "생성 중…"에 갇히는 일은 없습니다.

## 무대에서 하지 말 것

- `프리셋 전체 실행`을 연타하지 마세요. 이전 실행의 결과는 버려지지만(크래시는 없습니다)
  화면이 잠시 어수선해집니다.
- 프리셋 4개를 다 돌리면 호출이 20회 넘습니다. 리허설에서 한 번씩만 확인하세요.
- `?record=1`은 fixture 기록용입니다. 발표 중에는 붙이지 마세요.
